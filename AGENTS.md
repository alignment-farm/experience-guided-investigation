[PROMPT.md](PROMPT.md). This project owns workload development, methods, protocols,
execution, diagnosis and publication. Construct-2 owns theory and synthesis.
Begin a fresh ancillary session here and pursue the commissioned question.

- Develop a concrete neural learning target: using earlier experience to guide
  evidence search, inspection, testing and repair on a later unfamiliar change.
  Start with a LoRA-adapted tool-using learner; revise methods on evidence. A prose
  memory win is not required before developing the neural treatment.
- Reset conversations and ephemeral runtime state between episodes. Inventory
  retained artifacts and model state; isolate arms, verify reset/load behavior,
  and keep ordinary source access, code reuse and caching competent.
- Establish useful acquisition before interpreting retention or transfer.
  Diagnose failed acquisition purposefully; finite updates do not establish it.
  Preserve CC1–CC3, failures and original evaluations. Confirm claims developed
  through diagnosis on fresh material, without selecting on final outcomes.
- Keep future requirements, examiner implementations and confirmation tests out
  of participant access. Declare development feedback. Treat later checkpoints
  as changes within a history, not independent histories. Do not claim official
  benchmark comparability after changing its feedback or scoring.
- Complete useful behavior is primary. Track still-valid obligations and actual
  acquisition/learning/use/repair work. Disclose teacher work and unknown costs.
  Resource repayment is a further question, not a gate against learning research.
- Keep environments, implementation and evidence here. Inspect siblings read-only;
  pin reused artifacts and preserve licenses. Do not edit Construct-2, other
  studies or the derivative's active checkout. If using Construct Runtime,
  create an owned pinned dependency and describe any local modifications.
- Continue focused public-method discovery as local uncertainty sharpens. Record
  exact versions; distinguish inspected methods, author reports, local results
  and discovery leads. Use the arXiv query API for metadata, cache responses, use
  a descriptive User-Agent, and keep API/OAI requests on one connection at least
  three seconds apart across controlled clients; honor Retry-After.

- Coordinate heavy jobs and timing on shared machines. Start with a small pilot
  and set a bounded local resource budget before expansion. Preparation reserves
  no hardware and grants no additional spending allowance. Raise genuinely missing
  access or resources; routine scientific choices remain the study's responsibility.
- Use `uv` for Python and Docker/Compose where useful. Exclude credentials,
  environments, caches and base-model downloads from Git. Preserve manifests,
  raw evidence and small learned artifacts needed to judge and reproduce claims;
  document retrieval for larger artifacts. Keep tool side effects local.

Proceed through useful bounded diagnosis without returning routine choices to
root. Publication and root acceptance do not revoke the commission. Before
standing down, assess the best next step and stop on explanatory progress,
a demonstrated limitation or a concrete resource constraint. A treatment win
is unnecessary. Keep process and documentation proportional to the research.
